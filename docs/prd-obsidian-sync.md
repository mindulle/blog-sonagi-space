# 📝 [PRD & Decision Record] 옵시디언 - MS To Do 동기화 파이프라인 (v2.0)

## 1. 개요 및 피벗(Pivot) 사유
* **초기 기획 (v1.0):** 옵시디언 데일리 노트를 웹에서 직접 수정하기 위해 모바일 웹 대시보드 UI를 커스텀으로 개발하려 했음.
* **피벗 사유:** MS To Do 앱이 이미 모바일 편의성(위젯, 푸시 알림, 반복 일정 관리 등)에서 압도적으로 훌륭함. 단순히 옵시디언에 기록을 남긴다는 장점 하나만을 위해 이를 포기하고 커스텀 웹 대시보드를 바닥부터 구축(재발명)하는 것은 오버엔지니어링이며 비효율적이라고 판단함.
* **최종 방향 (v2.0):** **모바일에서의 일정 관리는 기존대로 MS To Do 앱을 사용하되, 자동화 파이프라인(n8n)을 구축하여 하루의 루틴과 완료된 일정들을 옵시디언 데일리 노트 원본에 동기화(자동 커밋)하는 백엔드 아키텍처로 변경.**

## 2. 사용자 스토리 (User Stories)
- [ ] 사용자로서 평소처럼 **MS To Do 앱**과 위젯을 사용해 가장 편리하게 할 일과 루틴을 체크한다.
- [ ] 사용자로서 내가 굳이 신경 쓰지 않아도, **정해진 시간(예: 매일 자정)이 되면 오늘 완료한 내역들이 내 옵시디언(GitHub) 데일리 노트 파일에 예쁘게 기록**되어 영구 보존된다.

## 3. 기술 스택 및 파이프라인 구조
* **프론트엔드/입력부:** MS To Do 앱 (모바일/PC)
* **오케스트레이션:** `n8n` (Workflow Automation)
  - MS To Do API 연동 (완료된 항목 추출)
  - 주기적인 크론(Cron) 트리거
* **백엔드/수정 로직:** Next.js API Routes (Webhook 수신) + AST Parser + GitHub API (Octokit)
  - `n8n`에서 추출된 데이터를 JSON 형태로 수신
  - AST(`remark`)를 통해 마크다운의 구조를 파악하고 데이터를 삽입/업데이트
  - GitHub에 Commit & Push (`sha`를 이용한 충돌 제어 적용)
* **저장소(SSOT):** GitHub 레포지토리의 마크다운 파일 (`llm-wiki`)

## 4. 보존된 핵심 로직 자산
대시보드 UI 코드는 폐기하였으나, 아래 두 가지 핵심 로직은 향후 파이프라인 API 구축 시 그대로 재사용한다.
- `lib/github.ts`: GitHub 토큰으로 안전하게 옵시디언 마크다운 파일을 읽어오고 커밋하는 모듈
- `lib/markdown.ts`: 정규식 대신 AST 구문 트리를 활용하여, 문서가 깨지지 않고 정확하게 특정 텍스트 항목의 체크박스 속성만 조작하는 안전한 파서
