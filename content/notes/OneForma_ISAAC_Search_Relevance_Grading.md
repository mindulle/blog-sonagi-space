# OneForma ISAAC Search Relevance Grading Guide

## 1. 프로젝트 개요 (Project Overview)

이 프로젝트는 사용자가 검색엔진에 검색어(Query)를 입력했을 때 표시되는 결과(Result)가 사용자의 의도(Intent)를 얼마나 잘 충족하는지 평가(Satisfaction Rating)하여 검색 품질을 향상시키는 작업입니다.

## 2. 평가 진행 4단계 (Process Overview)

1. **Understand the Query (검색어 이해):**
   - 검색어의 의미와 의도를 파악합니다.
   - 모호한 경우 웹 검색 링크(Research links)를 통해 정보를 수집합니다.
2. **Review the Result (검색 결과 검토):**
   - 웹 페이지, 뉴스, 지식 카드(Knowledge card), 지도, 앱 등 제공된 결과를 클릭하여 확인합니다.
3. **Validate the Result (유효성 검증):**
   - **CU (Content Unavailable):** 에러 페이지, 삭제된 페이지, 서버 점검, 유료 결제(Paywall/Subscription)로 인해 내용을 볼 수 없는 경우 (홈 화면으로 갈 수 있어도 CU 처리).
   - **Wrong Language:** 사용자의 국가 언어나 영어가 아닌 경우. (단, 영어는 항상 허용됨. 쿼리에 국가별 사이트가 명시된 경우 예외 적용).
   - **Inappropriate Content:** 성인물, 혐오 표현, 위험한 콘텐츠 등.
4. **Rate the Result (만족도 평가 - 4단계):**
   - **Highly Satisfying (HS):** 거의 모든 사용자가 원하는 완벽한 정답. 추가적인 클릭이나 노력 없이 즉시 의도를 해결해주는 공식/권위적 결과. _(※ "살 빼는 법"과 같은 조언이나 의견을 구하는 질문에는 절대 HS를 줄 수 없음)_
   - **Satisfying (S):** 검색어와 잘 일치하고 유용한 정보를 제공하지만, 완벽한 공식 결과는 아니거나 한 번의 클릭 등 약간의 사용자 노력이 필요한 경우.
   - **Somewhat Satisfying (SS):** 관련성은 있으나 완벽하지 않음. 사용자가 원하는 정보의 일부만 있거나 약간 거리가 있는 경우.
   - **Not Satisfying (NS):** 사용자의 의도를 전혀 충족하지 못하는 경우.

## 3. 일반 규칙 및 팁 (General Guidelines & User Effort)

- **기본 환경:** 모든 검색은 **Apple 기기(예: Safari)**에서 이루어진다고 가정합니다.
- **사용자 노력 (User Effort):** 사용자가 정답을 찾기 위해 더 많은 클릭이나 스크롤 등 "노력"을 해야 할수록 등급은 낮아집니다. (일반적으로 1~2번의 클릭은 S나 SS가 가능)
- **직접적 답변 (Direct Answers):** 지식 카드(Knowledge Card)나 Info Card처럼 즉각적으로 정답을 알려주는 결과가 링크를 눌러야 하는 결과보다 높은 점수를 받습니다.

## 4. 특수 상황 및 카테고리별 평가 기준 (Special Case Handling)

### 🗺 지도 / 위치 검색 (Maps)

- **체인점 + 명시적 위치 (예: KFC Milano):**
  - 공식 웹사이트 & 위치 안내 페이지가 1-click 거리 → **S (만족)**
  - 비공식(서드파티) 웹사이트 & 1-click 거리 → **SS (다소 만족)** _(비공식 사이트는 절대 S 불가)_
  - 위치 페이지가 1-click 보다 더 멀리 있는 경우 → **NS (불만족)**

### 📰 뉴스 / 웹사이트 (News & Websites)

- **Paywall (유료 결제 장벽):** 기사나 콘텐츠가 유료 구독이나 회원가입에 막혀 보이지 않는다면, 설령 홈 화면으로 돌아가서 다른 뉴스를 볼 수 있다고 해도 **CU (Content Unavailable)**로 처리합니다.
- **유지보수 중 (Under Maintenance):** 일시적으로 이용할 수 없는 웹사이트도 **CU** 처리.

### 🛍 쇼핑 / 제품 (Products)

- **브랜드 제품 검색:** 타사 쇼핑몰(서드파티)이라도 검색한 제품을 잘 팔고 있다면 **S**가 될 수 있습니다.
- **품절 (Out of Stock) 규칙:**
  - **구체적 특정 모델** (예: "iPhone 14 Pro Max 512GB"): 품절 상태라도 그 특정 페이지를 보여주는 것이 최선이므로 **감점하지 않음**.
  - **일반적 제품** (예: "USB-C 어댑터"): 대체품이 많은 흔한 물건인데 품절 페이지를 보여주면, 사용자가 번거로워하므로 **감점(Downgrade)**.

### 🌐 네비게이셔널 쿼리 (Navigational Query)

- **특정 사이트 이동 의도:** "go to Facebook"처럼 특정 사이트를 가고자 하는 검색어는 해당 웹페이지로 연결되는 결과가 **HS (Highly Satisfying)**입니다.
- 로그인이 필요해 콘텐츠를 못 보더라도 목적 자체가 '접속'이므로 높은 점수를 부여합니다.

### 📸 웹 이미지 (Web Images)

여러 장의 이미지 세트가 결과로 나올 경우 **모든 이미지**가 다음 조건을 만족해야 **HS**를 받습니다.

1. 정확한 피사체를 보여줄 것
2. 선명하게 보일 것 (가려지거나 너무 멀지 않음)
3. 이미지의 메인 포커스가 피사체일 것
4. 피사체의 가장 "대표적인(Representative)" 최신/유명한 모습을 보여줄 것
5. 중복(Duplicates)이 없을 것

## 5. 최종 작업 체크리스트 (Checklist)

1. 검색어, 위치, 날짜 등 맥락(Context)을 파악한다.
2. 필요시 검색 엔진을 이용해 검색어의 의미를 정확히 리서치한다.
3. 결과 링크(Result)가 정상적으로 채점 가능한 상태인지 확인한다. (오류, 언어, 부적절성 확인)
4. 채점이 불가능하면 CU, NS 등의 사유를 코멘트로 남긴다.
5. 채점이 가능하면 HS, S, SS, NS 4가지 척도로 평가를 진행한다.
6. 복수의 결과가 주어진 경우 각각 독립적으로 평가한다.
7. `Submit` 버튼을 눌러 제출하고 다음 작업으로 넘어간다.
