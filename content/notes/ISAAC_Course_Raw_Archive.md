## Project Overview

Project Overview

🎯Project Aim

Search engine users are trying to accomplish a task (or achieve a goal) that requires some information or quick access to some other resource, such as an app, news or some information. This project aims to improve the search results when the user issues a query.

🛠️Task

What will be given: You will receive a query and its corresponding result, along with contextual details like user location and query date.

What you need to do: Research the query, review the result, validate it for issues, and assign a satisfaction rating based on the guidelines.

## Search Results

Search Results

Two Kinds of Search Results

There are two kinds of search results you may be asked to grade:

WEB/NEWS RESULT
INFO CARD RESULT

This is a result that comes from the news or the web. Since anyone can create a web page or news article, we have no control over the quality or accuracy of the results content. Therefore, these results need to be validated, as explained in the next section.

In this orientation module, there will be places where the instructions are different depending on whether the result is from a web/news source or from an info card source. 

If the instructions are not provided, please check if the results are labelled as "Top Hit". These results may be either a web/news result or an info card result. You will need to judge which type of result they are based on the information provided and the way it is displayed.
If your grading project involves only one type of result, then once you determine if it is a web/news or info card source, you can follow the same instructions the whole time. If it involves multiple kinds of results, then you will need to pay attention to the result type every time to make sure you’re following the right set of instructions.

## Step 4: Rate the Result

Step 4: Rate the Result

Once you've validated that the result is appropriate and accessible, the next step is to assign a satisfaction rating based on how well the result meets the user's search need. There are four satisfaction levels. Click the tabs below to learn about them.

HIGHLY SATISFYING (HS)
SATISFYING (S)
SOMEWHAT SATISFYING (SS)
NOT SATISFYING (NS)

The result is exactly what almost all users would want.

It is authoritative, accurate, up-to-date, and directly answers the query.

No extra effort is needed from the user.

Examples:

Query: "instagram" → Result: Instagram app

Query: "how many stomachs does a cow have" → Result: Knowledge card with the correct answer

Note: Results for advice or opinion-based queries (e.g., “how to lose weight”, "best Beatles song") can never be rated HS.

Key Principles to Consider when Grading a Result

Consider degrees of separation: the more steps away from the query topic, the lower the rating

Think about meaning, not just matching words

Factor in user effort: direct answers are better

Evaluate source quality: trustworthy, well-written, and unbiased sources are preferred

## Special Case Handling

Special Case Handling

This lesson provides instructions on how to grade results in special cases. Here's a simplified overview of the topics it covers.

Ambiguous Queries (Multiple Interpretations)

If one meaning is clearly dominant, grade based on that.

If no dominant meaning, downgrade results that would otherwise be Highly Satisfying to Satisfying.

Locale Sensitivity

Grade based on whether the result matches the user’s location or locale-specific needs.

Mismatched locales may lead to lower grades or Not Satisfying.

English Results in Non-English Locales

English results may still be graded but may be downgraded depending on the locale’s fluency in English.

Redirected Pages

Grade the page you land on after redirection, not the original URL.

Apps

Grade based on whether the app is official, commonly used, or relevant to the query.

News

Consider timeliness, relevance, and whether the article is truly about the query topic.

Maps

Grade based on distance, accuracy, and whether the user likely wanted a map result.

1. Grade on what is visible

2. “Permanently closed”

3. Distant results are not always NS

4. Keep in mind Intent and Distance

Web Video

Grade based on relevance, popularity, and whether the video matches the query intent.

If a query specifically refers to a particular video (e.g., “lemonade official video,” “Stepanov elements of programming lecture”), the desired result should be graded as Highly Satisfying regardless of its popularity.

For other results, and for more general queries where many different video results could satisfy the user's need (e.g., “guitar lesson”), then popularity may factor into your decision; you may want to grade a video with millions of views higher than a similar one with only a handful.

When deciding on your grade, think about whether video results are what the user is looking for when typing the query.

You are not required to watch the entire video to arrive at a rating.

Dictionary, Stocks, Weather, Knowledge/Answers, Sports, and “Learn About” Queries

Grade based on the accuracy and completeness of the information shown directly in the card.

Dictionary: Is the user seeking a definition or a concept? If the card precisely answers the need, this is Highly Satisfying. In all cases, it must be the correct interpretation of that word.

Stocks: Check for correct stock symbol and presence of price.

Weather: The result’s location should match the location specified in the query (e.g. “weather boston”), or the user’s location if the location is not mentioned in the query.

Answers: Grade on what is visible.

Web Results (Suggested Web Sites)

Grade based on whether the result is official, relevant, and satisfies the query intent.

Please click on the thumbnail and grade the destination page (after redirects).

If a user issues a navigational query, and the result is the web page the user asked for, it should be graded as Highly Satisfying. This is true even if the page requires a log-in to view that cannot be bypassed. This is because it perfectly addresses the user’s search need (i.e., intent), which is navigating to that website.

When a user asks to go to a web page, it is called a navigational query. For example:

“go to Facebook.” The user mentions going to the website. This is a literal navigational query.

“faceb" and “facebook.com
(opens in a new tab)
" don’t mention going to the site, but it is implied.

Note: Always do research!

“x.” This is an ambiguous query. You cannot assume this is a navigational query without doing research. A web search shows no dominant meaning. If the result is the website x.com
(opens in a new tab)
, this should be graded as Satisfying.

Web Images

Grade the entire image set based on clarity, relevance, and uniqueness of images.

A group of web images should be graded as a single result. Check to see if all the images have the following properties:

The image displays the correct subject. The image must actually show the subject of the query. For example, if the query is  “dodecahedron,” the image must actually show that geometric figure and not some other one. Missing images (or ones that do not load) do not have this property.

The subject is clearly shown. All images in the set must clearly show the subject of the query. The subject should not be blocked, out of focus, too far away, or otherwise difficult to see clearly.

The subject is the focus of the image. In cases where the image includes multiple people or objects, it should be clear who or what is the subject of the query. (For example, if the query is “Joe Biden,” it’s fine to have people in the background of a picture of President Biden giving a speech, but it’s not fine to have a picture of Presidents Biden and Macron shaking hands.)

The image shows a representative version of the subject. For example, if the query is the name of a currently popular actor, the image should show that person as they look today (or how their character looks in a currently popular movie), not how they looked many years ago. If the query is the name of a famous person from the past who is no longer alive, the image should show them as they were best known. For example, if the query is “Richard Nixon,” a picture should show him during the time he was U.S. president, not 20 years later when he was near the end of his life.

No duplicates. The images in the set should all be different.

If ALL the images have all of the above properties, grade the result Highly Satisfying. Otherwise, downgrade the results as shown in the following table.

Product Searches

If the product is out of stock, grade depends on whether the item is specific or general.

If the user is searching for a product and the result is a page where the product can be purchased, but the item is unavailable or out-of stock, you may want to lower the grade in certain cases:

If the query describes something very specific, the user usually wants only that item. Showing the product page for the item is the best you can do, even if the item is out of stock so that result should not be penalized. Example queries:

“our missing hearts by celeste ng” [a specific book; the user doesn’t want any book]

“iPhone 14 pro max 512gb” [a specific model and configuration of a product]

If the query describes something general, or where there are reasonable substitutes, the user will probably rather see an in-stock substitute rather than an out-of-stock exact match. So, you should lower the grade of the out-of-stock result. Example queries:

USB to usb-c adapter [there are many different, equally good ones from different brands]

Bounty paper towels 12-pack [the user might be just as happy with two 6-packs of the same brand]

Flights

Information on Flight Cards should always be verified before assigning a satisfaction grade.

If the query date is more than 14 days old, do your best to verify the information with a web search.

If the information still can not be verified after a web search, you may assume the information on the card is correct and proceed to grade the result based on the guidelines, i.e., how well the result answered the user’s query.
